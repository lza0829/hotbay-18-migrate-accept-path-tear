# 热档片间（Hotbay）

影院素材分区温层：登记 → 冷热迁移 → 保留销毁 → 目录互证。

- 前端 http://127.0.0.1:6300
- API http://127.0.0.1:11300
- `docker compose up -d --build`

## 温层迁移口径（全局唯一）

本系统只贯彻一种架构：**以相邻一级为准（递进沉降）**。

- 温层顺序 `热档(0) → 温档(1) → 冷档(2)`，级差 = 落点序号 − 现行序号；
- 仅接受**级差绝对值为一**的迁移：热↔温、温↔冷；
- **热→冷跨两级禁止一笔直达**，整笔拒绝，必须先落温档；冷→热同理；
- 级差为零（同层）同样拒绝。

口径的唯一事实源是后端 `app/services/core.py::migration_rule()`：
递进规则页（`GET /api/递进规则`）的九对矩阵、迁移发起的拒单拒因、前端目标温层置灰，
全部由这同一个谓词重放，不存在第二套判定，也不允许只改拒因文案。

## 温层与目录归属同刷

- 温层与目录归属前缀一一对应：`热档=hot/`、`温档=warm/`、`冷档=cold/`；
- 迁移完成在**同一事务**内更新分区温层列、分区 `object_prefix`、素材对象键、目录清单对象键；
- 迁移单记录迁前快照（`snapshot_tier/snapshot_prefix`），失败整笔回滚到迁前快照，不留半截态；
- 目录互证会校验分区现行温层能重放出归属前缀，抓住「温层已改、目录未跟」。

## 并发与拒单

- 库级部分唯一索引保证同一分区至多一张「执行中」迁移单，并发双迁只有第一张落成，第二张落「已拒绝」（`double-migration`）；
- 完成动作有状态翻转闸门，并发完成同一单只生效一次；
- 拒单同样写迁移单（状态`已拒绝`）与 `migrate_audit` 审计表，拒因是结构化 `reject_code` + 文案，而非裸字符串。

## 边界

只覆盖热/冷路径级差与温层-目录联动；「完成时目录与温层谁先落、按件自标」属另立需求，不在此范围。
